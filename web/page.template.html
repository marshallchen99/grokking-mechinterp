Mechanistic interpretability · reproduction

A network that memorised for 14,379 steps, then learned trigonometry

A one-layer transformer is shown 30% of the addition table mod 113 and asked to fill in the rest. It memorises what it was shown in 158 steps, sits at chance on everything else for fourteen thousand more — and then, with nothing visible changing, generalises. This page takes the finished network apart to show what was forming in that silence.

01 · the task

The model is never told the rule

It sees pairs of symbols and an answer. Nothing says these are numbers, that + means addition, or that there is a modulus. Shrunk to mod 5 so it fits on a page, the job is to fill in the question marks from the cells it was shown:

At p = 113 that is 3,830 cells shown and 8,939 hidden. Two strategies both score 100% on the visible cells. Memorise — there is ample room for a lookup table — which says nothing at all about the hidden cells. Or find the rule. Gradient descent takes the first road, because memorising pays immediately and a general circuit pays nothing until it is finished.

04 · the algorithm

It turned addition into rotation

Nothing in the architecture suggests trigonometry. What the trained weights do is represent each number as a point on a circle and exploit the fact that, on a circle, addition is just turning further: 

  a  ->  ( cos(w*a), sin(w*a) )        w = 2*pi*k/113, for four values of k

  cos(w*(a+b)) = cos(w*a)cos(w*b) - sin(w*a)sin(w*b)     <- attention + MLP
  sin(w*(a+b)) = sin(w*a)cos(w*b) + cos(w*a)sin(w*b)

  logit(c)  proportional to   sum over k of  cos( w_k * (a + b - c) )

The last line is a matched filter. When c = a + b every term has phase zero and they peak together; for any other c the phases disagree and the terms cancel. Wraparound is free — the circle is already periodic, so there is no "subtract 113 if too big" step anywhere in the network.

05 · causal tests

Cut it out and the model dies

Everything above is correlational: the weights look like the algorithm. These edit the weights and re-run the whole network, so the intervention propagates the way a real change would. The control rows are what make the result mean anything — deleting any four of fifty-six frequencies removes some of the embedding's norm.

06 · generality

Change the operation and the same circuit appears, rotated

Identical configuration; only the operation changes. The last two columns are the mechanism tests from section 04, so a row that groks with a low (a+b) score has found a different algorithm, not the same one.

07 · the same model, two coordinate systems

Multiplication only looks structureless

The nonzero residues mod 113 form a cyclic group of order 112 under multiplication, so re-indexing them by discrete logarithm turns a*b into dlog(a) + dlog(b) mod 112 — multiplication is addition, in the right coordinate. The reduction itself is published; what is measured here is whether the circuit is load-bearing in that basis.

10 · honesty

What this is and is not

Nothing here is a new discovery. The phenomenon is Power et al. (2022); the mechanism and the progress measures are Nanda et al. (2023). This is a from-scratch reproduction — own model, own Fourier tooling, own analysis — plus a few extensions.

The lead times are one run. Grokking time varies substantially across seeds, and one run is not a distribution.

Runs are reproducible in distribution, not bit-exact. Single-threaded, identical seeds give identical weights and the test suite asserts it. Multi-threaded they do not: PyTorch's CPU reductions do not fix their summation order, and two runs of the same code diverge in the loss by about 1e-4 within a hundred steps.

The loss is computed in float64. In float32, log-softmax quantises at 2-23 = 1.2e-7, so once the model has memorised the reported training loss bottoms out there. The entire phenomenon lives in the tens of thousands of steps after the training loss is nominally zero, so a loss floor is exactly the wrong artefact to have.
